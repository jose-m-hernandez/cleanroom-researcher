This directory holds the evaluation harness for these skills.

Every `claude -p` call goes through `experiments/EXP-0001/code/runner/claude_run.py`, which builds its environment from an allowlist, loads the plugin from a pinned git export (the repository named by `CPR_EVAL_PLUGIN_REPO`, which must be outside the clone and hold the pinned ref), and proves isolation per run (`experiments/EXP-0001/code/runner/isolation.py`). `python3 experiments/EXP-0001/code/runner/run.py preflight` checks the setup without a model call; `python3 experiments/EXP-0001/code/runner/run.py control` runs the five live controls and needs `CPR_EVAL_LIVE=1`. Account-level connectors load regardless of the setting sources, so every isolated run also passes `--strict-mcp-config` (with no `--mcp-config`), which excludes them; the plain control run counts the connectors it sees to prove the check can fire. The judge is a Claude model (Opus) grading a Claude model's (Sonnet's) outputs; a cross-family judge was attempted, but the CLI could not exclude user instructions, so the checks in place are schema-only labels and a mismatch control on the line matcher, and neither measures same-family leniency. The labels are checked against a human reading by the repository owner's blind audit of 100 judged answers (`audit-export`, `audit-score`; P:143). Probe answers are labelled one call per probe session, each label matched back by its probe id; a failed isolation proof excludes every label of that call, and a label that is missing, duplicated or malformed excludes that probe only.

## Running it

Ten of the 19 commands make no model call: `preflight`, `validate`, `install-verify`, `spend-rebuild`, `lint`, `report`, `seal`, `pilot-md`, `audit-export` and `audit-score`. The other 9 (`control`, `canary`, `judge-check`, `gen-fixture`, `install-check`, `run`, `score`, `pilot` and `author`) launch live runs and refuse without `CPR_EVAL_LIVE=1`.

1. `python3 experiments/EXP-0001/code/runner/run.py lint <fixtures-root>` is P:249's clean-room lint: it runs the repository's vocabulary rules V1 to V4 and its barred-string scan over the fixture store, needs the list in `BARRED_STRINGS` or `BARRED_STRINGS_PATH` (DEAD, exit 2, without one), and prints entry numbers only.
2. `python3 experiments/EXP-0001/code/runner/run.py preflight` checks the sandbox root, the pinned `claude` version and the config, with no model call.
3. `CPR_EVAL_LIVE=1 CPR_EVAL_HOST_LEDGERS=<dir>[:<dir>...] python3 experiments/EXP-0001/code/runner/run.py control` runs the five isolation controls (live, sequential). The ledger directories are the host's own session ledgers; every regular file in them is read (gzip is out of scope). `CLAUDE_CONFIG_DIR` must be unset. It records the result in `gates.json` as the entry `C1-5` (PASS when all five pass, FAIL when a child process was spawned and the command did not end in PASS, nothing when it stopped before the first spawn, which is a setup error: a missing `claude` command, which starts no child process, records nothing), and it refuses to run again (exit 2, no launch) once an entry exists. While it runs it holds the lock `control.lock` in `$TMPDIR/cpr-eval/`, beside `gates.json`; a second `control` refuses (exit 2, no launch, nothing recorded) while that file exists, and the file is removed when the command ends, with one exception: if a child process was started but the `C1-5` result could not be written to `gates.json` (the command prints `control: STOP could not record C1-5 in gates.json; …`), the file is kept, so `control` keeps refusing. Do not delete it then: the control was launched, and a control is never re-run (P:239); what to record in `gates.json` is the repository owner's call. After a crash that kills the process the file stays, and nothing breaks it automatically. Before deleting it by hand, once no control run is live, check `gates.json` for a `C1-5` entry: a control that already launched is never re-run (P:239), and what to record is the repository owner's call. Two known limits: an interrupt that arrives after the child process has started but before the runner reports the start is counted as no launch, so nothing is recorded and the lock is removed; and an interrupt between creating the lock and registering it leaves a lock with nothing launched, which refuses until it is deleted by hand. Every gated command and `canary --type preserve` need `C1-5` PASS (step 11).
4. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py judge-check` runs the judge sanity cases (two calls: the seven probe cases as one batch, one of them an abstention probe with the neutral abstention gold, for which `abstained` and `correct` both pass; then the items case, each through the same per-run proof). It records the result in `gates.json` as the entry `JC` (PASS when every case passes, FAIL on a miss, nothing when it stops or errors before the result), and it refuses to run again (exit 2, no launch) once an entry exists, so a judge-check is never re-run. `gen-fixture`, `run` and `score` refuse until `JC` is PASS (step 11).
5. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py gen-fixture <id> [--fixtures-root <store>]` scripts a fixture's turns through the same runner (each turn proven), normalizes the transcript, checks it with the history token (resume control), and only then installs `transcript.jsonl`, `repo/` and `gen.json` into the fixture directory. `install-check <id>` repeats the resume control on an installed fixture. With `--fixtures-root` these commands read and write `<store>/<id>/` directly (the layout `author` writes) and refuse, before any other work, a store that does not exist or holds a symlink or a git folder; without it they use the in-repo `fixtures/<split>/<id>` folder. `install-verify` takes the same flag. `validate --fixtures-root <store>` runs the set rules (unique ids, category coverage, and with `--heldout-complete` at least 5 long fixtures) on the store and refuses a store that does not exist or holds a symlink or a git folder; it does not run the lint. Raw transcripts stay under `$TMPDIR/cpr-eval` and the user's own project directories, which are copied from and never deleted.
6. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py run [--split dev] [--fixtures all|<id>,<id>] [--fixtures-root <dir>] [--out <dir>] [--arms floor,baseline,oracle] [--seeds 5] [--budget-usd <n>] [--seal <dir> --preseal <dir>] [--supersede <ids> --repair-log <file>]` runs the arms: for each fixture and seed, a `/cpr:preserve quick` run on `--resume` of an installed copy of the fixture (the baseline, or any variant under `experiments/EXP-0001/code/arms/<name>/SKILL.md`), then one probe session per arm (no tools, no plugin, a sandbox holding only that arm's `CLAUDE.md`). Results go to `<out>` (required: a folder outside every clone, `experiments/EXP-0001/recorded/` included, for `run` and `pilot` alike; the other commands that take `--out` still accept a folder under `experiments/EXP-0001/recorded/`): `run.json`, `arms/`, `preserve/`, `probes/`; the full run records go to `$TMPDIR/cpr-eval/raw/<run id>/`, never into `<out>`. Each batch also writes `experiments/EXP-0001/recorded/runs/<run id>/isolation.json` into the repository, where `<run id>` is the name of the `--out` folder (not the raw run id below): it holds the labels of the checks the per-run proof applies, whether any included cell has an unresolved isolation failure (`isolated`; an excluded cell does not make it false), the number of excluded cells and the isolation check labels that excluded them (`excluded`), the proof counts and that run id, and nothing from a raw record (`pilot` writes it the same way). Each invocation that writes raw records mints one run id (`<UTC yyyymmddThhmmssZ>-<8 hex characters>`), records it in `run.json` as `raw_run_id`, and keys the raw folder by it; an existing raw folder refuses, a record is never overwritten, and a resumed run reuses the id in its own `run.json`. A unit whose result file exists is skipped, so a stopped run resumes. The per-run proof has isolation checks and outcome checks (`isolation.py`): a run that fails an isolation check is re-run once, and a second failure excludes the cell, which is listed in `run.json` and not run again; a run that fails only outcome checks (`result_error`, `ask_user`, `denials`, `over_cap`) is never re-run, and a preserve run is scored on the `CLAUDE.md` it left behind (a denial is also logged in `<out>/isolation-review.json`); a change of Claude Code version or model, or the budget, stops the run. Every run record carries `started_utc` (the launch time, UTC) and `pins` (Claude Code version, model, isolation mode, and the plugin ref when the run loaded the plugin). Before the seal, held-out runs use `floor` and `oracle` only (P:89, P:251, P:270): any other arm (`baseline`, a skill variant, or an unknown name) on held-out fixtures is refused (exit 2, before any launch) unless `--seal` names a seal folder (step 12) whose `manifest.txt` is committed in this repository, with the working file equal to the committed blob, and `--preseal` names the floor and oracle results the seal covers; the seal is verified against the fixtures and those results (a mismatch exits 1, outcome not determined), and `labels.json` and the floor and oracle session files are copied into `<out>` read-only. The same guard also needs `record.json` and the repair log committed in the same commit as `manifest.txt`, with the bytes on disk. The step-7 command of the protocol (`--split heldout --arms floor,oracle`) needs no seal. `--supersede <ids> --repair-log <file>` (comma-separated held-out fixture ids, and the repair log of step 16) is the floor and oracle re-check of repaired fixtures: it refuses (exit 2, before any launch and before anything moves) unless both flags are given, `--split` is `heldout`, `--arms` holds only `floor` and `oracle`, neither `--seal` nor `--preseal` is given, every id has the form `heldout-NNN-name`, is listed in `<out>/run.json`, has floor and oracle sessions there and is selected by `--fixtures`, the repair log has a `## <id>` line for it, and `<out>/superseded.json` does not exist yet (the flag runs once per folder), and `--seeds` equals the seed count recorded in `<out>/run.json`. After the live gate and the preflight it moves, and never deletes, each id's floor and oracle `probes/`, `arms/` and `preserve/` folders to `<out>/superseded/<UTC stamp>/` under the same relative paths (all or none), moves that id's `excluded_cells` entries out of `run.json` into the record, writes `<out>/superseded.json` (`ids`, the repair log's name and sha256, the `moved` paths, those `excluded_cells`, the `stamp` and `scoring_occasion` 2, with no absolute path) and runs only the units that are now missing, so every other unit is left alone and the folder holds every fixture that `seal --from` replays; a stopped batch is resumed by a plain `run`. It does not touch `score-passes.json`, `scores.json` or `labels.json` (step 7 says how the new record is read). `run.json` and `REPORT.md` give the counts. The config's isolation mode must be `sources`: `tempconfig` needs a credential and every command refuses it until the repository owner has ruled, with a security review; no credential variable is ever passed to a run. All spend is on the `evaluation` ledger.
7. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py score --from <out> [--fixtures-root <dir>] [--seal <dir>]` runs the judge sanity controls first (oracle recall at least 0.95; the cyclic mismatch control at most 0.05; either failing aborts the pass and is terminal, below), then labels every probe answer (one judge call per probe session) and every added memory line and writes `<out>/scores.json`, which also carries a `labels` block (the judge's label per arm, fixture, seed and probe, `null` for a missing one) that the human audit draws from. Labels are cached in `<out>/labels.json` by input content, the resolved judge model (`--model`, else the config pin) and a hash of the judge prompt and schema files, so a repeat pass costs nothing and a different judge or prompt never reuses a label; a batched call is one entry there, with its cost stored once. `scores.json` records the judge as `judge_model`, and `report` prints it from there (`run.json` is the fallback for older results). A probe whose label comes back missing or malformed is excluded, counted in `invalid.judge_labels_invalid`, and asked again alone on the next pass. A probe with no label for the floor or the oracle is dropped from the scorable set as `label_missing`; a probe with no label for another arm and seed is left out of that cell's numerator and denominator (it is not scored as incorrect), and so is an answer the session left out. Floor and oracle must hold exactly seeds 1 to N of `run.json`, or scoring refuses. An abstention probe the judge labels `correct` or `abstained` is not a false answer. A cell of recall, precision and placement needs the judge's line labels to number the added lines exactly 1 to N, each once; otherwise it is empty. Judge calls spend from the `evaluation` ledger and count against their own counter (`score-calls.json`, cap `score.max_judge_calls` in `config.json`), separate from the judge check's. The command counts its passes per mode (`normal`, and `final` when `--seal` is given) in `<out>/score-passes.json`: a pass counts as started before its first judge call and as aborted when it stops without a result (a scoring abort or the judge call cap); a third start in one mode is refused (exit 2), and two aborted passes in a mode stop it with the outcome not determined (exit 2). A pass that succeeds stamps its mode and number into `scores.json`, and `report` refuses a `scores.json` whose stamp is missing, from the other mode, or numbered beyond the passes started; a final report always needs the stamp, and another report needs it only when `score-passes.json` exists (the pilot writes `scores.json` without the command). A failed judge sanity control ends the scoring with the outcome not determined: the mode is marked `terminal` in `score-passes.json`, every later pass in it is refused (exit 2), and `report` refuses a `scores.json` of that mode. Scoring held-out results that hold an arm other than floor and oracle is the final scoring and needs `--seal` (step 12): the seal is verified first; floor and oracle labels come only from the sealed `labels.json`, which is re-hashed before it is read and never opened for writing (a floor or oracle label missing from it is not asked of the judge again); every new label goes to `labels-final.json`; and the scorable record must equal the sealed `record.json`, or scoring stops with the difference named. A results folder that holds `superseded.json` (step 6) is in scoring occasion `scoring_occasion` (2): `score` counts that occasion's passes in `<out>/score-passes-occasion-2.json`, with the rules above (two starts and a third refused, two aborts not determined, a failed judge sanity control final for that occasion and mode), and leaves `score-passes.json` as it was; the stamp in `scores.json` then carries `occasion`, and `report`, `audit-export` and `author --repair` accept only the last completed pass of the last occasion (a `scores.json` stamped for an earlier occasion is refused, a report that is not final included). A `superseded.json` that is not JSON, or whose `scoring_occasion` is not an integer of at least 2, stops `score` before any judge call. The rule is P:458: "Runs exactly twice" (P:130) applies to each scoring occasion: each pre-seal round, and the final scoring.
8. `python3 experiments/EXP-0001/code/runner/run.py report --from <out> [--out <dir>] [--seal <dir>] [--fixtures-root <dir>]` writes `REPORT.md` from `run.json` and `scores.json`, with no model call; the same inputs give the same bytes. A report on held-out results that hold an arm other than floor and oracle (the final report) needs `--seal` and `--audit <audit.json>` (exit 2 without either), verifies the seal first, and reads `record.json`, the repair log and `audit.json` (it refuses an `audit.json` with a non-finite kappa or an `n` below 1, and a `scores.json` without `labels` or `multi_value`). It states the outcome by P:66-70 (supports, counts against or inconclusive, by the baseline primary's 95% interval against T = 0.761), with the overrides of P:109 (fewer than 20 fixtures sealed: not determined), P:135 (more than 5 of the 25 fixtures left the primary: inconclusive) and P:146 (kappa below 0.6: inconclusive). It adds the primary recomputed with T's filter (P:158), the multi-value count (P:160) and the pre-seal repair log (P:156), and labels the paired-differences table exploratory (P:164; an A/A table with no rows is left out). `tests/data/exp0001-synthetic/` is a small invented results tree used to test that. When the results folder holds `superseded.json`, the report prints one line saying how many superseded excluded cells it no longer counts, and pointing at that file (in the per-run proof counts, or after the header when `run.json` has none); a `superseded.json` that is unreadable or malformed stops the report.
9. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py pilot --fixtures dev-001..dev-005 --seeds 3 --arms floor,baseline,oracle --budget-usd 34 [--out <dir>]` runs steps 6, 7 and 8 in one command (`--out` is required, as for `run`), then writes `PILOT.md`. The pilot runs on development fixtures only: held-out fixtures (`--split heldout` or a `heldout-` id) refuse with exit 2 before any launch, and there is no `--seal` flag. A range such as `dev-001..dev-005` expands against the fixtures that exist, and an unknown id refuses. `--budget-usd` is the most the evaluation ledger may grow in this invocation (preserve runs, probe sessions and judge calls alike); a value above `phase_caps.evaluation` refuses. A throttled unit (the run did not succeed and its result carries a limit message or HTTP 429, or a `rate_limit_event` has a status other than `allowed` and `allowed_warning`; the informational events every run carries do not count) waits `pilot.rate_limit_wait_s` (60 s) and resumes the batch once; a second throttle stops it. Also stopping the pilot, each named in `PILOT.md` (codes in the table below): a failed judge call isolation proof (S1), a failed judge sanity control (S11), fewer than `pilot.min_scorable_probes` (3) scorable probes on any fixture, a change in Claude Code version or model mid-batch (S10), and the cost cap. A pilot that finished but has any invalid judge label or missing probe answer is marked INCOMPLETE with that reason too. A stopped pilot writes what exists and marks `PILOT.md` INCOMPLETE with the reason; running the same command again resumes. `PILOT.md` reports per-call-type cost (API-price equivalent under a subscription), tokens and wall-clock, rate limits, judge calls successful against throttled (`score-calls.json` keeps a `throttled` count and the CLI's message text once a call is throttled), the plan usage Claude Code reports (or says it is not reported), the sanity controls, the scorable probes per fixture, the pins and the budget projection table. `python3 experiments/EXP-0001/code/runner/run.py pilot-md --from <out> [--fixtures-root <dir>] [--out <dir>]` rebuilds `PILOT.md` offline from the results directory and the fixtures' `gen.json`.
10. `CPR_EVAL_LIVE` must be `1` for any launch; `run_claude` refuses otherwise, and every launch names its phase (`control`, `judge`, `generation` or `evaluation`), and a launch is also refused once the sum of all ledgers has reached `spend_ceiling_usd`.
11. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py canary --type preserve|generation [--fixtures-root <dir>]` runs the canary C6 (`preserve`) or C7 (`generation`) once. It creates a file holding a fresh random token (256 bits) in the runner's own configuration folder (`CLAUDE_CONFIG_DIR`, else the `.claude` folder of the home folder in the run's environment; outside the sandbox) and a second token inside the sandbox, and asks a run of kind `canary` to read both. The run has a preserve run's tools and permissions; C7 swaps the Bash tools for the union of every spec's `allowed_bash` entries under `--fixtures-root` (the report names the specs that gave some). The canary file is removed afterwards, only if it is still the file the command made. The proof applies every isolation check and `result_error` and `over_cap`, but not `denials` or `ask_user` (a refused call is the expected result). The outcome is PASS (the sandbox token appears in the output, at least one call at the canary file was denied and none allowed, the canary token appears nowhere, the proof passes), ERROR (a clean run that made no call at the canary file) or FAIL (anything else). It is written to `$TMPDIR/cpr-eval/gates.json`, outside the repository, with the run id, the start time and the token (the scan needs it); the command prints the outcome and the run id only. A canary that has an entry in `gates.json` is never re-run. Every command that reaches `run_claude` (`judge-check`, `gen-fixture`, `install-check`, `run`, `score`, `pilot`, `author` and `canary --type generation`) refuses (exit 2, before any launch) unless `gates.json` records C6 PASS; `gen-fixture`, `run` and `score` also need `JC` PASS (step 4), and `gen-fixture` needs C7 PASS as well; a FAIL or ERROR entry for either canary, or a FAIL for `JC`, refuses them all; a missing, unreadable or malformed `gates.json` counts as not passed. `control` is not gated. `control` records C1-C5 as the entry `C1-5` in `gates.json` (no token), and every gated command and `canary --type preserve` refuse (exit 2, before any launch) unless it is PASS, checked before C6; a FAIL entry stops them all, and a control is never re-run (step 3).
12. `python3 experiments/EXP-0001/code/runner/run.py seal --fixtures-root <store> --from <floor-and-oracle results> --repair-log <file> --guide <file> --count-rule <file> --out <dir>` (every flag required; no model call) seals the held-out fixtures. In order, stopping at the first failure with nothing written: after the flag and `--out` checks, the code's repository has no uncommitted change to a tracked file (`git status --porcelain --untracked-files=no`; a dirty path is named relative to the repository, a git failure refuses, untracked files are ignored; exit 2); C6 and C7 are both PASS and the scan finds neither canary token nor the runner's account name (case-insensitive) in any `transcript.jsonl` under the store (a hit is named by fixture and pattern, never by text; the normalizer replaces the account name in any letter case as a whole word, and a name glued to a letter, digit or underscore is not replaced, so the scan refuses it: a stated limit); the results hold no arm other than floor and oracle (listed in `run.json` or present as a folder under `probes/`, `preserve/` or `arms/`); then it writes `manifest.txt` (a sha256 line per file under the store, sorted by path), `record.json` (per fixture the scorable, dropped and excluded probe ids, the fixtures dropped or replaced with their reasons, and the text of `--count-rule`), `seal.json` (the sha256 of the pre-seal `labels.json`, of every floor and oracle session file, of the guide, the count rule, the manifest, the record and the repair log, with `started_utc` and the code's git HEAD) and `repair-log/<name>`; `seal.json` also holds `audit_seed` (20261022, P:299), and `verify` reports `changed:audit_seed` when it is missing or differs. When `--from` holds a `superseded.json` (step 6), `seal` copies it into the seal folder and records its sha256 in `seal.json` under `superseded`, and `verify` re-hashes that copy. A fixture with fewer than 3 scorable probes (the minimum the pilot also uses) is listed in `excluded_fixtures` with that reason and its count, and `report` does not count it as sealed. Every path in these files is relative; `labels.json` and the session files are hashed, never copied. `--out` follows the same rule as the other `--out` flags and must not exist. The command does not commit: committing the folder is the repository owner's step.
13. `python3 experiments/EXP-0001/code/runner/run.py audit-export --from <final results> --seal <dir> --fixtures-root <store> --out <dir>` (every flag required; no model call) writes the human audit's blinded sample (P:293-306). In order, stopping at the first failure with nothing written: `--out` is refused or exists (exit 2); the seal does not verify, or its `audit_seed` is not 20261022, or the results are not the final scoring (held-out results with a baseline arm), or `scores.json` has no `labels` block, or its scorable record differs from the sealed `record.json` (exit 1, outcome not determined). `audit-export` refuses a `scores.json` that fails the same pass-stamp check as `report`. The frame is every baseline answer the judge labelled on a non-abstention probe, over all seeds (an excluded probe, an excluded baseline cell, a missing answer and an UNKNOWN answer are out). The draw takes 34 `incorrect`, 33 `correct` and 33 `abstained` answers (a label with fewer takes all of them and the shortfall goes to the others), stratified by probe type with at least 5 per cell, by `random.Random(20261022).sample` over the sorted ids `fixture/seed/probe`, a fresh generator per cell. It writes `items.json` (what the judge saw, in shuffled order, with no arm, fixture, seed, type or label), `owner-labels.json` (empty, for the owner to fill in: a label and whether the answer names more than one value) and `key.json` (the source and judge label of each item, the frame sizes, shares and allocation, and the mechanical multi-value flag), and prints one line with the counts and no figure. An answer names more than one value when its probe has at least one stale answer and the answer contains, ignoring letter case, both the gold answer and at least one stale answer; probes without stale answers are not counted (a stated limit). Stated limit: the export happens after the final scoring and before the report, and nothing in the code stops an operator from opening `scores.json`, which holds the primary figures, before labelling is done; not opening it is a procedure. The `labels` block of `scores.json` also shows the judge's label for every answer, so the owner should not open `scores.json` before labelling either. A second stated limit: the report trusts the `audit.json` it is given; nothing ties that file to these results except the operator's procedure.
14. `python3 experiments/EXP-0001/code/runner/run.py audit-score --key <key.json> --labels <owner-labels.json> --out <dir>` (every flag required; no model call) writes `audit.json`: Cohen's kappa over all items against the 0.6 bar, raw agreement, kappa and agreement per probe type, the judge-minus-person difference (P:159) on the scorable items with each judge label weighted by its frame size over its sampled count, per fixture, with a 10000-resample cluster bootstrap over fixtures seeded with the run's `rng_seed`, and the agreement of the owner's multi-value answers with the mechanical rule. A labels file that does not match the key (a missing or extra item, a label outside the three, a non-boolean) exits 1.
15. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py author --prompt <file> --guide <file> --out <store> [--extra <file>] [--only-ids <id>,<id>] [--replaces <id>,<id>]` makes one call with no tools (`notools`: `--tools ""`, no output cap, the run timeout), charged to its own `authoring` bound of $3.00 (4 x $0.75), counted under the $55 ceiling and not under the generation cap, and needs the C1-5 and C6 gates (not C7). The prompt sent is the prompt file, a blank line, the guide and, with `--extra`, a blank line and that file; the sha256 of each input is recorded, not the extra text. The reply is split mechanically: a header line holding a held-out id, then a fenced block; a block that parses as JSON is written byte for byte as `<store>/<id>/spec.json` (an existing id folder is never overwritten); authoring repairs and reformats nothing (a repair call is made only with `--repair`, step 16). `--out` must be outside every clone, including under `experiments/EXP-0001/recorded/`. The command prints counts and labels (`<id>: <label>` from the spec validator), never spec text. At most 4 calls are made in all, the repair call of step 16 included (`author-calls.json`; a refused fifth call and a failed isolation proof both leave the count as it is), and a call that fails the isolation proof writes no spec (exit 1). `--replaces` names the ids a call replaces: at most 3 replacements in all (`author-replacements.json`, entries added once the proof passes), a replacement is never itself replaced, and a call writes at most as many specs as ids it names. Each call that reached a launch adds a row to `author-runs.json` (run number, mode, start time, version, model, proof outcome, input hashes, ids written, cost); the mode is `author`, `replace` or `repair`, and a row with no mode is read as `author`. The files are under `$TMPDIR/cpr-eval/`.
16. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py author --repair --from <floor-and-oracle results> --fixtures-root <store> --guide <file> --out <new store>` makes the one repair call (P:252-256) through the same launch as step 15: the same pins, isolation proof and `notools`. `--repair` takes no `--prompt`, `--extra`, `--replaces` or `--only-ids` (each refuses, exit 2): the runner builds the prompt itself. The runner selects the evidence (P:253), never the owner: from `<results>/scores.json` it takes each active non-abstention probe whose floor and oracle labels are all present and that the floor answered correctly in any seed or the oracle answered correctly in fewer than a majority of its seeds (the negation of the filter in `score`), and a probe with a missing label is left out and counted. The blind agent (P:252) receives the guide, the `spec.json` of each fixture that holds a selected probe and, for each selected probe, its question, its gold answer and each seed's floor answer and oracle answer with their labels; nothing else. The runner checks the reply: only selected fixture ids, each selected fixture present once, the same probe ids (no probe added or removed) and a spec the validator accepts. Only a reply that passes writes anything: `--out` (which must not exist and must lie outside every clone) is a new full store holding every file under `--fixtures-root` byte for byte, with the agent's `spec.json` written over each selected fixture's, built in a temporary folder beside `--out` and renamed into place; the repair log (the runner's own diff, field by field, and the labels that selected each probe, with no answer text; each change line carries the sha256 of the full old and new value, and a reorder of the probes is logged as `order changed`) is written beside it as `<out>.repair-log.md`, never inside the store. A reply that fails the check writes nothing and prints labels only (exit 1). One repair call is allowed: it counts toward the 4-call counter and the `authoring` bound of step 15, and a failed isolation proof or a refused reply uses it. Every refusal before the call (exit 2, no call counted, nothing written) names its label: `--from` or `--fixtures-root` missing, a baseline arm in the results, `scores.json` missing or not from a completed floor and oracle scoring pass, a symlink or a git folder in the store, a selected fixture that is a replacement, a repair call already made, or no probe selected. `--from` and `--fixtures-root` are only read. The owner runs `gen-fixture <id> --fixtures-root <new store>` on each repaired id, then `lint <new store>`, then `run --split heldout --arms floor,oracle --fixtures <repaired ids> --seeds 3 --fixtures-root <new store> --out <the original folder> --supersede <repaired ids> --repair-log <new store>.repair-log.md` (P:256; the old sessions are moved to `superseded/<stamp>/`, not deleted, step 6), and passes the repair log to `seal --repair-log`.

`experiments/EXP-0001/code/config.json` pins the Claude Code version, the model under test, the isolation mode, the plugin ref, the skill and agent allowlists, the instructions-attachment fact and the hook baseline that the control measured, the per-run budget cap (a finite number in (0, 5]), the per-phase spend caps (`phase_caps`: control, generation, evaluation; the judge check spends from control's), the ceiling on the sum of all ledgers (`spend_ceiling_usd`), and the judge block (judge model, call cap). The spend ledgers (`spend.json`, one total per phase; it also holds an `authoring` total, which is not a `phase_caps` key: its $3.00 bound is a constant in the code, held by the 4-call counter, which counts the repair call, at $0.75 a call, and it counts in the $55 ceiling) and the judge call counter (`judge-calls.json`) live under `$TMPDIR/cpr-eval/`, so their scope is one `TMPDIR`: a different `TMPDIR` starts from zero. A `--resume` turn's `total_cost_usd` is cumulative for the session, so each run record keeps it as `cost_usd_reported` and charges `cost_usd`, this invocation's own cost (reported minus the prior turn's reported value; a missing prior, a bad prior or a negative difference charges the full value, and a forked run is charged in full). `python3 experiments/EXP-0001/code/runner/run.py spend-rebuild` recomputes `spend.json` from the stored records the same way: a dry run that prints old and new per ledger, `--write` to apply.

| Code | Control |
| --- | --- |

## Limitations

- A host hook on an event the plugin also declares can hide within the declared count; the ledger check is the backstop.
- The guards defend against accidental leakage, not a hostile author.
