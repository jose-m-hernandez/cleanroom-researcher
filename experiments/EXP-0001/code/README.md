This directory holds the evaluation harness for these skills.

Every `claude -p` call goes through `experiments/EXP-0001/code/runner/claude_run.py`, which builds its environment from an allowlist, loads the plugin from a pinned git export (the repository named by `CPR_EVAL_PLUGIN_REPO`, which must be outside the clone and hold the pinned ref), and proves isolation per run (`experiments/EXP-0001/code/runner/isolation.py`). `python3 experiments/EXP-0001/code/runner/run.py preflight` checks the setup without a model call; `python3 experiments/EXP-0001/code/runner/run.py control` runs the five live controls and needs `CPR_EVAL_LIVE=1`. Account-level connectors load regardless of the setting sources, so every isolated run also passes `--strict-mcp-config` (with no `--mcp-config`), which excludes them; the plain control run counts the connectors it sees to prove the check can fire. The judge is a Claude model (Opus) grading a Claude model's (Sonnet's) outputs; a cross-family judge was attempted, but the CLI could not exclude user instructions, so the checks in place are schema-only labels and a mismatch control on the line matcher, and neither measures same-family leniency. A second labeller from another model, with human adjudication of disagreements, is planned and not yet built. Probe answers are labelled one call per probe session, each label matched back by its probe id; a failed isolation proof excludes every label of that call, and a label that is missing, duplicated or malformed excludes that probe only.

## Running it

1. The clean-room leak lint is not part of this port: there is no `lint` command.
2. `python3 experiments/EXP-0001/code/runner/run.py preflight` checks the sandbox root, the pinned `claude` version and the config, with no model call.
3. `CPR_EVAL_LIVE=1 CPR_EVAL_HOST_LEDGERS=<dir>[:<dir>...] python3 experiments/EXP-0001/code/runner/run.py control` runs the five isolation controls (live, sequential). The ledger directories are the host's own session ledgers; every regular file in them is read (gzip is out of scope). `CLAUDE_CONFIG_DIR` must be unset.
4. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py judge-check` runs the judge sanity cases (two calls: the seven probe cases as one batch, one of them an abstention probe with the neutral abstention gold, for which `abstained` and `correct` both pass; then the items case, each through the same per-run proof).
5. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py gen-fixture <id>` scripts a fixture's turns through the same runner (each turn proven), normalizes the transcript, checks it with the history token (resume control), and only then installs `transcript.jsonl`, `repo/` and `gen.json` into the fixture directory. `install-check <id>` repeats the resume control on an installed fixture. Raw transcripts stay under `$TMPDIR/cpr-eval` and the user's own project directories, which are copied from and never deleted.
6. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py run [--split dev] [--fixtures all|<id>,<id>] [--fixtures-root <dir>] [--out <dir>] [--arms floor,baseline,oracle] [--seeds 5] [--budget-usd <n>]` runs the arms: for each fixture and seed, a `/cpr:preserve quick` run on `--resume` of an installed copy of the fixture (the baseline, or any variant under `experiments/EXP-0001/code/arms/<name>/SKILL.md`), then one probe session per arm (no tools, no plugin, a sandbox holding only that arm's `CLAUDE.md`). Results go to `<out>` (required: a folder outside the clone, or one under `experiments/EXP-0001/recorded/`): `run.json`, `arms/`, `preserve/`, `probes/`; the full run records go to `$TMPDIR/cpr-eval/raw/<run>/`, never into `<out>`. A unit whose result file exists is skipped, so a stopped run resumes; an isolation failure or the budget stops it. All spend is on the `evaluation` ledger.
7. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py score --from <out> [--fixtures-root <dir>]` runs the judge sanity controls first (oracle recall at least 0.95; the cyclic mismatch control at most 0.05; either failing aborts the pass), then labels every probe answer (one judge call per probe session) and every added memory line and writes `<out>/scores.json`. Labels are cached in `<out>/labels.json` by input content, the resolved judge model (`--model`, else the config pin) and a hash of the judge prompt and schema files, so a repeat pass costs nothing and a different judge or prompt never reuses a label; a batched call is one entry there, with its cost stored once. `scores.json` records the judge as `judge_model`, and `report` prints it from there (`run.json` is the fallback for older results). A probe whose label comes back missing or malformed is excluded, counted in `invalid.judge_labels_invalid`, and asked again alone on the next pass. A probe with no label for the floor or the oracle is dropped from the scorable set as `label_missing`; a probe with no label for another arm and seed is left out of that cell's numerator and denominator (it is not scored as incorrect), and so is an answer the session left out. Floor and oracle must hold exactly seeds 1 to N of `run.json`, or scoring refuses. An abstention probe the judge labels `correct` or `abstained` is not a false answer. A cell of recall, precision and placement needs the judge's line labels to number the added lines exactly 1 to N, each once; otherwise it is empty. Judge calls spend from the `evaluation` ledger and count against their own counter (`score-calls.json`, cap `score.max_judge_calls` in `config.json`), separate from the judge check's.
8. `python3 experiments/EXP-0001/code/runner/run.py report --from <out> [--out <dir>]` writes `REPORT.md` from `run.json` and `scores.json` alone, with no model call; the same inputs give the same bytes. `tests/data/exp0001-synthetic/` is a small invented results tree used to test that.
9. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py pilot --fixtures dev-001..dev-005 --seeds 3 --arms floor,baseline,oracle --budget-usd 30 [--out <dir>]` runs steps 6, 7 and 8 in one command (`--out` is required, as for `run`), then writes `PILOT.md`. A range such as `dev-001..dev-005` expands against the fixtures that exist, and an unknown id refuses. `--budget-usd` is the most the evaluation ledger may grow in this invocation (preserve runs, probe sessions and judge calls alike); a value above `phase_caps.evaluation` refuses. A throttled unit (the run did not succeed and its result carries a limit message or HTTP 429, or a `rate_limit_event` has a status other than `allowed` and `allowed_warning`; the informational events every run carries do not count) waits `pilot.rate_limit_wait_s` (60 s) and resumes the batch once; a second throttle stops it, and any other proof failure stops at once. Also stopping the pilot, each named in `PILOT.md` (codes in the table below): an isolation failure (S1), a failed judge sanity control (S11), fewer than `pilot.min_scorable_probes` (3) scorable probes on any fixture, a change in Claude Code version or model mid-batch (S10), and the cost cap. A pilot that finished but has any invalid judge label or missing probe answer is marked INCOMPLETE with that reason too. A stopped pilot writes what exists and marks `PILOT.md` INCOMPLETE with the reason; running the same command again resumes. `PILOT.md` reports per-call-type cost (API-price equivalent under a subscription), tokens and wall-clock, rate limits, judge calls successful against throttled (`score-calls.json` keeps a `throttled` count and the CLI's message text once a call is throttled), the plan usage Claude Code reports (or says it is not reported), the sanity controls, the scorable probes per fixture, the pins and the budget projection table. `python3 experiments/EXP-0001/code/runner/run.py pilot-md --from <out> [--fixtures-root <dir>] [--out <dir>]` rebuilds `PILOT.md` offline from the results directory and the fixtures' `gen.json`.
10. `CPR_EVAL_LIVE` must be `1` for any launch; `run_claude` refuses otherwise, and every launch names its phase (`control`, `judge`, `generation` or `evaluation`), and a launch is also refused once the sum of all ledgers has reached `spend_ceiling_usd`.

`experiments/EXP-0001/code/config.json` pins the Claude Code version, the model under test, the isolation mode, the plugin ref, the skill and agent allowlists, the instructions-attachment fact and the hook baseline that the control measured, the per-run budget cap (a finite number in (0, 5]), the per-phase spend caps (`phase_caps`: control, generation, evaluation; the judge check spends from control's), the ceiling on the sum of all ledgers (`spend_ceiling_usd`), and the judge block (judge model, call cap). The spend ledgers (`spend.json`, one total per phase) and the judge call counter (`judge-calls.json`) live under `$TMPDIR/cpr-eval/`, so their scope is one `TMPDIR`: a different `TMPDIR` starts from zero. A `--resume` turn's `total_cost_usd` is cumulative for the session, so each run record keeps it as `cost_usd_reported` and charges `cost_usd`, this invocation's own cost (reported minus the prior turn's reported value; a missing prior, a bad prior or a negative difference charges the full value, and a forked run is charged in full). `python3 experiments/EXP-0001/code/runner/run.py spend-rebuild` recomputes `spend.json` from the stored records the same way: a dry run that prints old and new per ledger, `--write` to apply.

## Committed results and which code made them

`dev-baseline-1seed` and `pilot-20261017` were scored by earlier code: their `labels.json` keep the old model-less keys, and their questions were reworded afterwards, so scoring them again would need judge calls and nothing does. Their `scores.json` and `REPORT.md` are as first committed. `report --from` reproduces `REPORT.md` byte for byte only under the code that first committed them; under the current code it differs (checked: `REPORT.md` differs for both). `dev-baseline-1seed-r1` was re-scored offline with the current code and regenerates byte for byte under HEAD.

## Codes in the output

The isolation controls that `control` runs (five live runs, in this order of reporting):

| Code | Control |
| --- | --- |
| C1 | A plain, unisolated run: the instrument must fire (it sees host files and markers) and it proves this CLI version writes the instructions attachment |
| C2 | An isolated run with the plugin: the per-run isolation proof passes |
| C3 | An isolated run with no plugin: the plugin is absent, and its hook count is the recorded baseline |
| C4 | An isolated run over a seeded session log: the hook-output canary and the ledger rows are checked |
| C5 | `/cpr:preserve quick` on `--resume`, headless: it must be able to change `CLAUDE.md` |

The pilot's stop codes, as named in `PILOT.md` and its output:

| Code | Stop |
| --- | --- |
| S1 | An isolation proof failed (on a preserve run, a probe session or a judge call) |
| S4 | A rate limit persisted after the one wait and retry, or a judge call was throttled |
| S10 | Claude Code's version or the model changed mid-batch |
| S11 | A judge sanity control failed (oracle recall below 0.95 or mismatch recall above 0.05) |

## Limitations

- A host hook on an event the plugin also declares can hide within the declared count; the ledger check is the backstop.
- The guards defend against accidental leakage, not a hostile author.
