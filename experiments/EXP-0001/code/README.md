This directory holds the evaluation harness for these skills.

Every `claude -p` call goes through `experiments/EXP-0001/code/runner/claude_run.py`, which builds its environment from an allowlist, loads the plugin from a pinned git export (the repository named by `CPR_EVAL_PLUGIN_REPO`, which must be outside the clone and hold the pinned ref), and proves isolation per run (`experiments/EXP-0001/code/runner/isolation.py`). `python3 experiments/EXP-0001/code/runner/run.py preflight` checks the setup without a model call; `python3 experiments/EXP-0001/code/runner/run.py control` runs the five live controls and needs `CPR_EVAL_LIVE=1`. Account-level connectors load regardless of the setting sources, so every isolated run also passes `--strict-mcp-config` (with no `--mcp-config`), which excludes them; the plain control run counts the connectors it sees to prove the check can fire. The judge is a Claude model (Opus) grading a Claude model's (Sonnet's) outputs; a cross-family judge was attempted, but the CLI could not exclude user instructions, so the checks in place are schema-only labels and a mismatch control on the line matcher, and neither measures same-family leniency. The labels are checked against a human reading by the repository owner's blind audit of 100 judged answers (`audit-export`, `audit-score`; P:143). Probe answers are labelled one call per probe session, each label matched back by its probe id; a failed isolation proof excludes every label of that call, and a label that is missing, duplicated or malformed excludes that probe only.

## Running it

Ten of the 18 commands make no model call: `preflight`, `validate`, `install-verify`, `spend-rebuild`, `lint`, `report`, `seal`, `pilot-md`, `audit-export` and `audit-score`. The other 8 (`control`, `canary`, `judge-check`, `gen-fixture`, `install-check`, `run`, `score` and `pilot`) launch live runs and refuse without `CPR_EVAL_LIVE=1`.

1. `python3 experiments/EXP-0001/code/runner/run.py lint <fixtures-root>` is P:249's clean-room lint: it runs the repository's vocabulary rules V1 to V4 and its barred-string scan over the fixture store, needs the list in `BARRED_STRINGS` or `BARRED_STRINGS_PATH` (DEAD, exit 2, without one), and prints entry numbers only.
2. `python3 experiments/EXP-0001/code/runner/run.py preflight` checks the sandbox root, the pinned `claude` version and the config, with no model call.
3. `CPR_EVAL_LIVE=1 CPR_EVAL_HOST_LEDGERS=<dir>[:<dir>...] python3 experiments/EXP-0001/code/runner/run.py control` runs the five isolation controls (live, sequential). The ledger directories are the host's own session ledgers; every regular file in them is read (gzip is out of scope). `CLAUDE_CONFIG_DIR` must be unset. It records the result in `gates.json` as the entry `C1-5` (PASS when all five pass, FAIL when a child process was spawned and the command did not end in PASS, nothing when it stopped before the first spawn, which is a setup error: a missing `claude` command, which starts no child process, records nothing), and it refuses to run again (exit 2, no launch) once an entry exists. While it runs it holds the lock `control.lock` in `$TMPDIR/cpr-eval/`, beside `gates.json`; a second `control` refuses (exit 2, no launch, nothing recorded) while that file exists, and the file is removed when the command ends. After a crash that kills the process the file stays, and it must be deleted by hand once no control run is live; nothing breaks it automatically. Every gated command and `canary --type preserve` need `C1-5` PASS (step 11).
4. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py judge-check` runs the judge sanity cases (two calls: the seven probe cases as one batch, one of them an abstention probe with the neutral abstention gold, for which `abstained` and `correct` both pass; then the items case, each through the same per-run proof).
5. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py gen-fixture <id>` scripts a fixture's turns through the same runner (each turn proven), normalizes the transcript, checks it with the history token (resume control), and only then installs `transcript.jsonl`, `repo/` and `gen.json` into the fixture directory. `install-check <id>` repeats the resume control on an installed fixture. Raw transcripts stay under `$TMPDIR/cpr-eval` and the user's own project directories, which are copied from and never deleted.
6. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py run [--split dev] [--fixtures all|<id>,<id>] [--fixtures-root <dir>] [--out <dir>] [--arms floor,baseline,oracle] [--seeds 5] [--budget-usd <n>] [--seal <dir> --preseal <dir>]` runs the arms: for each fixture and seed, a `/cpr:preserve quick` run on `--resume` of an installed copy of the fixture (the baseline, or any variant under `experiments/EXP-0001/code/arms/<name>/SKILL.md`), then one probe session per arm (no tools, no plugin, a sandbox holding only that arm's `CLAUDE.md`). Results go to `<out>` (required: a folder outside the clone, or one under `experiments/EXP-0001/recorded/`): `run.json`, `arms/`, `preserve/`, `probes/`; the full run records go to `$TMPDIR/cpr-eval/raw/<run id>/`, never into `<out>`. Each invocation that writes raw records mints one run id (`<UTC yyyymmddThhmmssZ>-<8 hex characters>`), records it in `run.json` as `raw_run_id`, and keys the raw folder by it; an existing raw folder refuses, a record is never overwritten, and a resumed run reuses the id in its own `run.json`. A unit whose result file exists is skipped, so a stopped run resumes. The per-run proof has isolation checks and outcome checks (`isolation.py`): a run that fails an isolation check is re-run once, and a second failure excludes the cell, which is listed in `run.json` and not run again; a run that fails only outcome checks (`result_error`, `ask_user`, `denials`, `over_cap`) is never re-run, and a preserve run is scored on the `CLAUDE.md` it left behind (a denial is also logged in `<out>/isolation-review.json`); a change of Claude Code version or model, or the budget, stops the run. Every run record carries `started_utc` (the launch time, UTC) and `pins` (Claude Code version, model, isolation mode, and the plugin ref when the run loaded the plugin). Before the seal, held-out runs use `floor` and `oracle` only (P:89, P:251, P:270): any other arm (`baseline`, a skill variant, or an unknown name) on held-out fixtures is refused (exit 2, before any launch) unless `--seal` names a seal folder (step 12) whose `manifest.txt` is committed in this repository, with the working file equal to the committed blob, and `--preseal` names the floor and oracle results the seal covers; the seal is verified against the fixtures and those results (a mismatch exits 1, outcome not determined), and `labels.json` and the floor and oracle session files are copied into `<out>` read-only. The step-7 command of the protocol (`--split heldout --arms floor,oracle`) needs no seal. `run.json` and `REPORT.md` give the counts. The config's isolation mode must be `sources`: `tempconfig` needs a credential and every command refuses it until the repository owner has ruled, with a security review; no credential variable is ever passed to a run. All spend is on the `evaluation` ledger.
7. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py score --from <out> [--fixtures-root <dir>] [--seal <dir>]` runs the judge sanity controls first (oracle recall at least 0.95; the cyclic mismatch control at most 0.05; either failing aborts the pass), then labels every probe answer (one judge call per probe session) and every added memory line and writes `<out>/scores.json`, which also carries a `labels` block (the judge's label per arm, fixture, seed and probe, `null` for a missing one) that the human audit draws from. Labels are cached in `<out>/labels.json` by input content, the resolved judge model (`--model`, else the config pin) and a hash of the judge prompt and schema files, so a repeat pass costs nothing and a different judge or prompt never reuses a label; a batched call is one entry there, with its cost stored once. `scores.json` records the judge as `judge_model`, and `report` prints it from there (`run.json` is the fallback for older results). A probe whose label comes back missing or malformed is excluded, counted in `invalid.judge_labels_invalid`, and asked again alone on the next pass. A probe with no label for the floor or the oracle is dropped from the scorable set as `label_missing`; a probe with no label for another arm and seed is left out of that cell's numerator and denominator (it is not scored as incorrect), and so is an answer the session left out. Floor and oracle must hold exactly seeds 1 to N of `run.json`, or scoring refuses. An abstention probe the judge labels `correct` or `abstained` is not a false answer. A cell of recall, precision and placement needs the judge's line labels to number the added lines exactly 1 to N, each once; otherwise it is empty. Judge calls spend from the `evaluation` ledger and count against their own counter (`score-calls.json`, cap `score.max_judge_calls` in `config.json`), separate from the judge check's. Scoring held-out results that hold an arm other than floor and oracle is the final scoring and needs `--seal` (step 12): the seal is verified first; floor and oracle labels come only from the sealed `labels.json`, which is re-hashed before it is read and never opened for writing (a floor or oracle label missing from it is not asked of the judge again); every new label goes to `labels-final.json`; and the scorable record must equal the sealed `record.json`, or scoring stops with the difference named.
8. `python3 experiments/EXP-0001/code/runner/run.py report --from <out> [--out <dir>] [--seal <dir>] [--fixtures-root <dir>]` writes `REPORT.md` from `run.json` and `scores.json`, with no model call; the same inputs give the same bytes. A report on held-out results that hold an arm other than floor and oracle (the final report) needs `--seal` and `--audit <audit.json>` (exit 2 without either), verifies the seal first, and reads `record.json`, the repair log and `audit.json` (it refuses an `audit.json` with a non-finite kappa or an `n` below 1, and a `scores.json` without `labels` or `multi_value`). It states the outcome by P:66-70 (supports, counts against or inconclusive, by the baseline primary's 95% interval against T = 0.761), with the overrides of P:109 (fewer than 20 fixtures sealed: not determined), P:135 (more than 5 of the 25 fixtures left the primary: inconclusive) and P:146 (kappa below 0.6: inconclusive). It adds the primary recomputed with T's filter (P:158), the multi-value count (P:160) and the pre-seal repair log (P:156), and labels the paired-differences table exploratory (P:164; an A/A table with no rows is left out). `tests/data/exp0001-synthetic/` is a small invented results tree used to test that.
9. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py pilot --fixtures dev-001..dev-005 --seeds 3 --arms floor,baseline,oracle --budget-usd 34 [--out <dir>]` runs steps 6, 7 and 8 in one command (`--out` is required, as for `run`), then writes `PILOT.md`. The pilot runs on development fixtures only: held-out fixtures (`--split heldout` or a `heldout-` id) refuse with exit 2 before any launch, and there is no `--seal` flag. A range such as `dev-001..dev-005` expands against the fixtures that exist, and an unknown id refuses. `--budget-usd` is the most the evaluation ledger may grow in this invocation (preserve runs, probe sessions and judge calls alike); a value above `phase_caps.evaluation` refuses. A throttled unit (the run did not succeed and its result carries a limit message or HTTP 429, or a `rate_limit_event` has a status other than `allowed` and `allowed_warning`; the informational events every run carries do not count) waits `pilot.rate_limit_wait_s` (60 s) and resumes the batch once; a second throttle stops it. Also stopping the pilot, each named in `PILOT.md` (codes in the table below): a failed judge call isolation proof (S1), a failed judge sanity control (S11), fewer than `pilot.min_scorable_probes` (3) scorable probes on any fixture, a change in Claude Code version or model mid-batch (S10), and the cost cap. A pilot that finished but has any invalid judge label or missing probe answer is marked INCOMPLETE with that reason too. A stopped pilot writes what exists and marks `PILOT.md` INCOMPLETE with the reason; running the same command again resumes. `PILOT.md` reports per-call-type cost (API-price equivalent under a subscription), tokens and wall-clock, rate limits, judge calls successful against throttled (`score-calls.json` keeps a `throttled` count and the CLI's message text once a call is throttled), the plan usage Claude Code reports (or says it is not reported), the sanity controls, the scorable probes per fixture, the pins and the budget projection table. `python3 experiments/EXP-0001/code/runner/run.py pilot-md --from <out> [--fixtures-root <dir>] [--out <dir>]` rebuilds `PILOT.md` offline from the results directory and the fixtures' `gen.json`.
10. `CPR_EVAL_LIVE` must be `1` for any launch; `run_claude` refuses otherwise, and every launch names its phase (`control`, `judge`, `generation` or `evaluation`), and a launch is also refused once the sum of all ledgers has reached `spend_ceiling_usd`.
11. `CPR_EVAL_LIVE=1 python3 experiments/EXP-0001/code/runner/run.py canary --type preserve|generation [--fixtures-root <dir>]` runs the canary C6 (`preserve`) or C7 (`generation`) once. It creates a file holding a fresh random token (256 bits) in the runner's own configuration folder (`CLAUDE_CONFIG_DIR`, else the `.claude` folder of the home folder in the run's environment; outside the sandbox) and a second token inside the sandbox, and asks a run of kind `canary` to read both. The run has a preserve run's tools and permissions; C7 swaps the Bash tools for the union of every spec's `allowed_bash` entries under `--fixtures-root` (the report names the specs that gave some). The canary file is removed afterwards, only if it is still the file the command made. The proof applies every isolation check and `result_error` and `over_cap`, but not `denials` or `ask_user` (a refused call is the expected result). The outcome is PASS (the sandbox token appears in the output, at least one call at the canary file was denied and none allowed, the canary token appears nowhere, the proof passes), ERROR (a clean run that made no call at the canary file) or FAIL (anything else). It is written to `$TMPDIR/cpr-eval/gates.json`, outside the repository, with the run id, the start time and the token (the scan needs it); the command prints the outcome and the run id only. A canary that has an entry in `gates.json` is never re-run. Every command that reaches `run_claude` (`judge-check`, `gen-fixture`, `install-check`, `run`, `score`, `pilot` and `canary --type generation`) refuses (exit 2, before any launch) unless `gates.json` records C6 PASS; `gen-fixture` also needs C7 PASS; a FAIL or ERROR entry for either canary refuses them all; a missing, unreadable or malformed `gates.json` counts as not passed. `control` is not gated. `control` records C1-C5 as the entry `C1-5` in `gates.json` (no token), and every gated command and `canary --type preserve` refuse (exit 2, before any launch) unless it is PASS, checked before C6; a FAIL entry stops them all, and a control is never re-run (step 3).
12. `python3 experiments/EXP-0001/code/runner/run.py seal --fixtures-root <store> --from <floor-and-oracle results> --repair-log <file> --guide <file> --count-rule <file> --out <dir>` (every flag required; no model call) seals the held-out fixtures. In order, stopping at the first failure with nothing written: after the flag and `--out` checks, the code's repository has no uncommitted change to a tracked file (`git status --porcelain --untracked-files=no`; a dirty path is named relative to the repository, a git failure refuses, untracked files are ignored; exit 2); C6 and C7 are both PASS and the scan finds neither canary token nor the runner's account name (case-insensitive) in any `transcript.jsonl` under the store (a hit is named by fixture and pattern, never by text; the normalizer replaces the account name in any letter case as a whole word, and a name glued to a letter, digit or underscore is not replaced, so the scan refuses it: a stated limit); the results hold no arm other than floor and oracle (listed in `run.json` or present as a folder under `probes/`, `preserve/` or `arms/`); then it writes `manifest.txt` (a sha256 line per file under the store, sorted by path), `record.json` (per fixture the scorable, dropped and excluded probe ids, the fixtures dropped or replaced with their reasons, and the text of `--count-rule`), `seal.json` (the sha256 of the pre-seal `labels.json`, of every floor and oracle session file, of the guide, the count rule, the manifest, the record and the repair log, with `started_utc` and the code's git HEAD) and `repair-log/<name>`; `seal.json` also holds `audit_seed` (20261022, P:299), and `verify` reports `changed:audit_seed` when it is missing or differs. Every path in these files is relative; `labels.json` and the session files are hashed, never copied. `--out` follows the same rule as the other `--out` flags and must not exist. The command does not commit: committing the folder is the repository owner's step.
13. `python3 experiments/EXP-0001/code/runner/run.py audit-export --from <final results> --seal <dir> --fixtures-root <store> --out <dir>` (every flag required; no model call) writes the human audit's blinded sample (P:293-306). In order, stopping at the first failure with nothing written: `--out` is refused or exists (exit 2); the seal does not verify, or its `audit_seed` is not 20261022, or the results are not the final scoring (held-out results with a baseline arm), or `scores.json` has no `labels` block, or its scorable record differs from the sealed `record.json` (exit 1, outcome not determined). The frame is every baseline answer the judge labelled on a non-abstention probe, over all seeds (an excluded probe, an excluded baseline cell, a missing answer and an UNKNOWN answer are out). The draw takes 34 `incorrect`, 33 `correct` and 33 `abstained` answers (a label with fewer takes all of them and the shortfall goes to the others), stratified by probe type with at least 5 per cell, by `random.Random(20261022).sample` over the sorted ids `fixture/seed/probe`, a fresh generator per cell. It writes `items.json` (what the judge saw, in shuffled order, with no arm, fixture, seed, type or label), `owner-labels.json` (empty, for the owner to fill in: a label and whether the answer names more than one value) and `key.json` (the source and judge label of each item, the frame sizes, shares and allocation, and the mechanical multi-value flag), and prints one line with the counts and no figure. An answer names more than one value when its probe has at least one stale answer and the answer contains, ignoring letter case, both the gold answer and at least one stale answer; probes without stale answers are not counted (a stated limit). Stated limit: the export happens after the final scoring and before the report, and nothing in the code stops an operator from opening `scores.json`, which holds the primary figures, before labelling is done; not opening it is a procedure. The `labels` block of `scores.json` also shows the judge's label for every answer, so the owner should not open `scores.json` before labelling either. A second stated limit: the report trusts the `audit.json` it is given; nothing ties that file to these results except the operator's procedure.
14. `python3 experiments/EXP-0001/code/runner/run.py audit-score --key <key.json> --labels <owner-labels.json> --out <dir>` (every flag required; no model call) writes `audit.json`: Cohen's kappa over all items against the 0.6 bar, raw agreement, kappa and agreement per probe type, the judge-minus-person difference (P:159) on the scorable items with each judge label weighted by its frame size over its sampled count, per fixture, with a 10000-resample cluster bootstrap over fixtures seeded with the run's `rng_seed`, and the agreement of the owner's multi-value answers with the mechanical rule. A labels file that does not match the key (a missing or extra item, a label outside the three, a non-boolean) exits 1.

`experiments/EXP-0001/code/config.json` pins the Claude Code version, the model under test, the isolation mode, the plugin ref, the skill and agent allowlists, the instructions-attachment fact and the hook baseline that the control measured, the per-run budget cap (a finite number in (0, 5]), the per-phase spend caps (`phase_caps`: control, generation, evaluation; the judge check spends from control's), the ceiling on the sum of all ledgers (`spend_ceiling_usd`), and the judge block (judge model, call cap). The spend ledgers (`spend.json`, one total per phase) and the judge call counter (`judge-calls.json`) live under `$TMPDIR/cpr-eval/`, so their scope is one `TMPDIR`: a different `TMPDIR` starts from zero. A `--resume` turn's `total_cost_usd` is cumulative for the session, so each run record keeps it as `cost_usd_reported` and charges `cost_usd`, this invocation's own cost (reported minus the prior turn's reported value; a missing prior, a bad prior or a negative difference charges the full value, and a forked run is charged in full). `python3 experiments/EXP-0001/code/runner/run.py spend-rebuild` recomputes `spend.json` from the stored records the same way: a dry run that prints old and new per ledger, `--write` to apply.

## Codes in the output

The isolation controls that `control` runs (five live runs, in this order of reporting):

| Code | Control |
| --- | --- |
| C1 | A plain, unisolated run: the instrument must fire (it sees host files and markers) and it proves this CLI version writes the instructions attachment |
| C2 | An isolated run with the plugin: the per-run isolation proof passes |
| C3 | An isolated run with no plugin: the plugin is absent, and its hook count is the recorded baseline |
| C4 | An isolated run over a seeded session log: the hook-output canary and the ledger rows are checked |
| C5 | `/cpr:preserve quick` on `--resume`, headless: it must be able to change `CLAUDE.md` |

The pilot's stop codes, as named in `PILOT.md` and its output:

| Code | Stop |
| --- | --- |
| S1 | An isolation proof failed on a judge call (a preserve run or probe session that fails one is re-run once, then its cell is excluded) |
| S4 | A rate limit persisted after the one wait and retry, or a judge call was throttled |
| S10 | Claude Code's version or the model changed mid-batch |
| S11 | A judge sanity control failed (oracle recall below 0.95 or mismatch recall above 0.05) |

## Limitations

- A host hook on an event the plugin also declares can hide within the declared count; the ledger check is the backstop.
- The guards defend against accidental leakage, not a hostile author.
